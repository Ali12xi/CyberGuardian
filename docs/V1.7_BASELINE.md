OBSERVATION 5 — Coverage credits are mutually exclusive on header coverage

The three coverage credits cannot all fire together:
- observabilityAwareTransportCredit → requires coverage.headers !== "full"
- observableEdgeHardening → requires coverage.headers !== "full"
- edgeManagedHeaderSurface → requires coverage.headers === "full"

Philosophical interpretation: These represent distinct evidentiary 
regimes — "full visibility" vs "partial/no visibility + edge hardening." 
Likely intentional architectural distinction preventing double-counting 
of inferred trust.

Decision: Documented as semantic discovery. NOT tested as invariant — 
this remains an internal semantic boundary, not external behavior.

OBSERVATION 6 — Limited coverage has no numeric score cap

Score caps work differently for partial vs limited coverage:
- partial → capped at 82 (or 88 with edge hardening)
- limited → no numeric cap applied

Philosophical interpretation: Reflects "not observable ≠ insecure" 
philosophy. Limited observability means we cannot judge with confidence, 
which is epistemically different from partial visibility.

However: formalization may be incomplete. A synthetic contradictory 
input (all stages failed yet healthy ssl/headers fields) can still 
produce a high score — this is a philosophical edge exposure, not 
necessarily a defect.

Decision: Documented as philosophical observation. Article 14 protects 
ONLY graceful degradation (no crash, deterministic, overall === "limited") 
— NOT "limited remains uncapped forever." Future sprints may decide 
on soft caps, confidence attenuation, or degraded ceilings.

OBSERVATION 7 — Redirect layered semantics (same pattern as Day 2)

Same architectural duality as Day 2's Observation 4 (TLS layered 
semantics):
- noRedirectChain positive → keys off redirects.suspicious (deprecated flag)
- threat/penalties → keys off redirects.analysis.intent (structured field)

Philosophical interpretation: Likely architectural evolution — older 
flag-based scoring layer + newer structured semantic layer coexisting. 
Same "claimed vs observed" duality seen in TLS scoring.

Decision: Documented. Article 10 asserts threat only (not score), 
acknowledging the layered semantics without freezing them.

OBSERVATION 8 — IPv4-mapped IPv6 blocked wholesale

::ffff:x.x.x.x is blocked regardless of whether x.x.x.x is public 
or private, because expandIPv6 rejects any string containing ".". 

Effect:
- ::ffff:10.0.0.1 (private) → blocked ✅ (correct)
- ::ffff:8.8.8.8 (public)   → blocked ⚠️ (over-blocking)

Decision: Documented as implementation residue. NOT constitutionalized.
Behavior is fail-closed (security-positive). May evolve in future 
if legitimate use cases emerge.

OBSERVATION 9 — Trailing-dot localhost defense-in-depth

isBlockedHostname("localhost.") returns false (static rule misses).
However, DNS resolution to 127.0.0.1 catches it via the answer 
validation layer.

Decision: Constitutionalized as Article 28, asserting rejection 
WITHOUT pinning the specific blockedReason (environment DNS varies).
Defense-in-depth invariant protected.

OBSERVATION 10 — Fail-closed on parse failure

parseIPv4 / expandIPv6 return treated-as-blocked when parsing fails.
This is a deliberate-looking safe default.

Decision: Implicit systemic principle. NOT constitutionalized as 
an explicit article — covered ambiently by other tests.

OBSERVATION 11 — Redundant 169.254.169.254 clause

Line 147 re-checks AWS metadata host already covered by 169.254.0.0/16.
Harmless residue.

Decision: Ignored. Article 23 protects the AWS metadata invariant

OBSERVATION 12 — Strict port allowlist

Only default ports (80, 443) pass. Non-default ports rejected even 
for public hosts (e.g., https://example.com:8443 → unsupported_port).

Decision: Constitutionalized as Article 29. Framed as "scanner scope 
policy" (not "8443 is insecure") — intentional constraint to standard 
web protocols.

OBSERVATION 13 — Alternate IP encodings defense-in-depth

http://2130706433 (decimal for 127.0.0.1) is canonicalized by the 
URL constructor before validator inspects it — so defense actually 
occurs via IP-literal branch, NOT DNS as initially expected.

Decision: Constitutionalized as Article 30. Asserts rejection WITHOUT 
pinning the implementation route (per friend's edit 3). The invariant 
is rejection of alternate loopback representations, NOT which layer 
catches it.

DISCOVERY: Defense-in-depth in the validator goes deeper than expected:
- Layer 1: URL canonicalization (handles decimal/hex/octal)
- Layer 2: IP literal check (catches canonicalized private IPs)
- Layer 3: DNS resolution (unused safety net for the encoding case)
